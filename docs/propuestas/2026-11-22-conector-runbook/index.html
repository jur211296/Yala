Qué cambió respecto a lo que encontró Dan

Los SQL viejos no se aplican. Dan tenía razón: los mcp0_0* abortarían y, si pasaran, la web perdería su rol. El camino nuevo cambia solo el id del conector en el hook que corre hoy y añade su barrido.
site_url sí hace falta. Hoy no lo usa nadie, pero Supabase manda el navegador a site_url + /oauth/consent para pedir el permiso. Lo medí en staging. La web no se entera porque solo lee el código de esa redirección; el conector sí la sigue.
Los pasos 6 y 8 viejos sobran. Hook, servidor OAuth, Apple, Google y email ya están. Nunca se manda la config de Auth entera: solo la clave que cambia.
La dependencia del gateway ya se cumple. El PR de «Cuenta sola» entró en 2.3 esta mañana; el gateway ya se puede desplegar desde 2.3.

Riesgos

El despliegue del gateway sube todo lo de 2.3. Lo que corre hoy es 2.3 con «Cuenta sola», que ya entró. La comprobación es comparar /config antes y después, y que solo falte la 0004.
El id del cliente vive en wrangler.toml. Si no vuelve a 2.3, el siguiente despliegue desde el repo se niega por el PENDIENTE. No rompe nada, pero hay que hacerlo.
El e2e automático no corre en producción porque entra con contraseña. La validación es la conexión de Jürgen del paso 7.
