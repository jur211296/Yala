<task type="auto">
  <name>Task 1: Revisar patrones de SwiftData y optimizar queries</name>
  <files>Neto/App/ViewModels/*.swift, Neto/App/Logic/**/*.swift</files>
  <action>
    1. Buscar patrones N+1 potenciales:
       - Loops que hacen fetch dentro del loop
       - @Query sin predicates específicos
       - Acceso a relaciones en loops sin prefetch
    2. Revisar que FetchDescriptors usan predicates apropiados
    3. Verificar que no hay fetches redundantes (mismo query múltiples veces)
    4. Documentar queries principales y su eficiencia
    5. Si se encuentran problemas, aplicar fixes:
       - Añadir predicates para limitar resultados
       - Usar batch fetching donde aplique
       - Cachear resultados que no cambian frecuentemente
  </action>
  <verify>Build exitoso, no hay warnings relacionados con queries</verify>
  <done>Queries revisados y optimizados donde necesario</done>
</task>

<task type="auto">
  <name>Task 2: Revisar body complexity en vistas principales</name>
  <files>Neto/App/Views/Panel/*.swift, Neto/App/Views/Statistics/*.swift</files>
  <action>
    1. Revisar vistas principales:
       - PanelView
       - TrendsTabView
       - CategoriesTabView
       - RecordsTabView
    2. Buscar cálculos costosos dentro de body:
       - Sorting/filtering en cada render
       - Cálculos complejos sin memoización
       - Formateo de fechas/números repetido
    3. Aplicar optimizaciones:
       - Mover cálculos a computed properties con cache
       - Usar @State para valores derivados que cambian poco
       - Extraer subvistas para limitar re-renders
    4. Verificar uso de LazyVStack/LazyHStack en listas
  </action>
  <verify>Build exitoso</verify>
  <done>Vistas principales optimizadas, sin cálculos redundantes en body</done>
</task>
