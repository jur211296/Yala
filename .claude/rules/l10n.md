# Localización

- **iOS NO hace fallback per-key con idioma de SISTEMA.** El patrón "marker-only hereda vía fallback iOS" es FALSO: si la variante (`es-ES`/`es-AR`/`en-GB`/`pt-PT`) es el idioma del sistema, iOS resuelve `Bundle.main` contra esa `.lproj` y devuelve la **key cruda** si falta (afecta `ls()` Y los ~290 `NSLocalizedString` directos). El fallback manual de `ls()` solo corre con **override in-app** (`parentBundle != nil`). → **Toda key nueva DEBE quedar en las 4 variantes completas, no sparse.** Usa `qa/scripts/add-l10n-key.sh` (ya las materializa) y `LocalizationParityTests.variants_haveAllKeys_fromParent` lo enforcea. `es-419`/`en`/`pt-BR` son las referencias completas. Detalle en L10N.md.
- **Keys duplicadas en un mismo `.strings`: la ÚLTIMA declaración gana, silenciosamente** (ni el compilador ni la paridad lo detectan — `NSDictionary` colapsa al parsear). `LocalizationParityTests.noDuplicateKeys_inAnyLocale` lo enforcea leyendo los archivos FUENTE vía `#filePath` (app + widget target). Si alguna vez hay que dedupe: keys usadas para **matching por nombre persistido** (ej. `subcategory.balanceAdjustment` — seed + CSV import + InitialBalanceService) deben conservar el valor runtime actual o se duplican entidades de usuarios.
- **Idioma para prompts LLM: SIEMPRE `AppLocale.current.identifier`, NUNCA `Locale.current.identifier`.** `Locale.current` refleja la región de FORMATO (`AppleLocale`, ej. `es_PE`) y no cambia con el idioma de la UI (`AppleLanguages`) → app en inglés recibía respuestas del chat en español. `AppLocale.current` (→ `LanguageManager.resolved.locale`) es el SSOT: override in-app → `Locale.preferredLanguages` → `en`. `Locale.current.region` sí es la fuente correcta para PAÍS/modismos. Output LLM cacheado (ej. sugerencias de chat) debe incluir el idioma en la cache key.
- **El vocabulario de sesiones NO se «corrige» hacia la jerga interna.** Dentro (ADR, tickets, código) decimos *sesión privada* y *sesión en la nube*; **al usuario se le habla de dónde viven sus datos** — «Dónde viven tus datos» (`storage.title`), «Tu cuenta en tu iCloud privado» (`welcome.new.privateTitle`), «Tu cuenta en la nube» (`welcome.new.cloudTitle`). Los dos vocabularios conviven **a propósito** (decisión de Jürgen, 2026-09-09, ADR «Sesiones — dos ejes»): medido el 2026-09-10, **cero de los 4.128 strings ES** dice «sesión privada», «sesión en la nube» o «solo grupos», y así se queda. La correspondencia completa está en `docs/glosario.md`; el copy nuevo se revisa además contra `docs/planning/BRAND-VOICE.md` §7. No reescribas copy que ya funciona.
